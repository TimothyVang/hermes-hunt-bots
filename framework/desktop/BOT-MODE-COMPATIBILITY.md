None of these establishes guide parity, guest installation, provider access, or a live bot exchange.

Bot Mode is a bundled native Desktop UI over Hermes profiles and backend services. The intended topology is Windows Hermes Desktop connected deliberately to a dedicated Linux Hermes backend. Installing backend source or Bot Screen packages does not update the Windows renderer. OMP develops the product; it is not its orchestration runtime. Within a Temporal checkpoint, Hermes retains its native coordinator and delegation.

A later isolated source-mode Windows Desktop run displayed real app-owned VM firmware in an embedded tab, executed a bounded keyboard command, released control and powered the diskless VM off. No installed VMware was used for that path. That app-owned VM console was removed in SF8, so this is history and boot-console evidence only: it does not satisfy the Linux backend, remote Bot Screen, authenticated models or guide-parity gates below.

## Source discrepancies that block a full-support claim

1. **DM fallback:** `tools/bot_mode_dm.py:627–654` uses profile authority and refuses/retains unavailable delivery. The corresponding tests reject a quiet-CLI workaround, while the guide describes one. Preserve single-writer safety; reconcile the guide/version contract before claiming parity.
2. **Group transcript window:** the inspected canonical `_build_prompt` uses the last 24 delta lines, bounded by 128 KiB, rather than the guide's 200 messages / 32,000 characters / 8,000-character excerpts. Omission counting for the 24-line slice is not established.
3. **Canonical membership and room-link capability:** `gateway/session_group_controls.py` does not expose a member-edit RPC, reports `room_link.enabled: false`, and lacks the older TUI surface's replica/promote/demote methods. Discover actual `groups.capabilities`; never promise an unavailable RPC or silently switch authorities.
4. **Projection/hooks:** the TUI hosted-room projector and `on_room_member_activity` hook are not proof of identical behavior for canonical session-authority rooms. Test external member-session writes, reconnect and reconciliation on the actual negotiated path.
5. **Routines and auth wording:** Bot Chat routine delivery is an explicit choice rather than the current default. Desktop auth-sharing defaults and stripping cloned OAuth grants differ from a simplistic copy-and-sign-in description. Keep private sign-in and sharing decisions with the operator.

Authority transfer, where supported, requires quiescing writers, complete final replication, independently fencing the old writer and preventing restart, promotion, then demotion using the exact new owner and epoch. Desktop exit, network disconnection or `groups.stop` is not such a fence. Preserve divergent histories; demotion is not a merge.

- `test_hosted_room_discussion.py`: distinct-thread FIFO and stop fencing without blocking later messages.
- `test_bot_failure_reasons.py`: typed errors, auth-versus-quota precedence, retry eligibility.
